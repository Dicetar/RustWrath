Status vocabulary (pills used below)

  • open / live — bug verified in source at HEAD; user-visible or evidence-corrupting.
  • partial — some work landed at HEAD; the remainder is listed.
  • src-closed — fixed in source at HEAD but zero runtime proof (stale binary); verify, don't redo.
  • unproven — a change landed whose behavior/validity is unverified (potential regression the commits introduced).
  • by design — the logged event is a configuration outcome, not a defect.

Rules any agent must follow on this repo

  • Read-only, always: game install, server/DB, reference decompile, extracted FrameXML/GlueXML. Never commit game data, extracted UI files, credentials or local runtime state.
  • All Cargo runs go through sccache (.cargo/config.toml sets build.rustc-wrapper; a missing wrapper is a build failure — install sccache rather than bypassing). Check sccache --show-stats before claiming cache hits.
  • One owner per ticket. Never start a competing build/client or terminate another session to take a slot; revalidate stale PIDs before acting on them.
  • The owner enters credentials and drives gameplay. No unattended combat, no automated character create/delete, no competing login during an owner session.
  • Preserve dirty source and untracked evidence. Stage explicit owned paths only — no blanket staging, no reset/clean under dirty work.
  • Close bugs against their original symptom; separate source / compilation / focused checks / receiver behavior / visible gameplay. No alpha claim from tests alone.
  • A commit or staged DLL does not demonstrate live module activation (ADR-0002) — runtime acceptance is a separate gate.
  • Verification budget: keep targeted cases within ~20; don't fill the budget unnecessarily. Documentation work needs no build or run.

Ranked fix list — what is still wrong on 680c6eac

1Preflight mislabels every Wrath session as NET OFF P0 · EVIDENCE INTEGRITY live

lib.rs:467 sets connect: !capturing && wrath_config.is_none(), so a Wrath run always adds NetPlugin{connect:false} + NetOffline (game_plugins.rs:131-138) while the real loop is WrathNetPlugin. preflight.rs:101-111 warns from NetOffline alone, so every Wrath run logs "NET OFF — NOTHING on the wire path executes" — false. This corrupted the 2026-11-12 report and both research rounds.

Fix: make offline_notice Wrath-aware (suppress when the Wrath path owns the session, or name the real IO owner); keep stock capture mode's warning. Add a regression test: a Wrath session must not emit the banner.

2Spell modifier table widened to 96 bits in storage, consumers still 64-bit P0 · SILENT WRONG NUMBERS live

spell/mods.rs:30-33 BITS=96, range check 0..=95 (:136-139) — but diff() folds only (0..64) into u64 (:186) and collapses bits 64–96 into a boolean high_changed (:192); modifiers() accumulates 0..64u8. High-word Wrath SpellFamilyFlags are silently dropped → combat/loot numbers wrong with no error.

Fix: re-point read/apply/diff at the existing 96-bit accessor (benilla-formats/src/spells/mod.rs:401-409, [u32;3]) + one high-word unit test.
