## What was found (dig)

Round-2 research (`synthesis-2.md` in the research workspace) plus this round's dig confirmed
and extended:

1. **`680c6eac` broke the `benilla-app` build chain**: its `PetLoyalty.dbc made optional` change
   calls `PetLoyaltyNames::default()` (`pet_stats.rs:184`) without a `Default` impl — E0599,
   `benilla-formats` fails to compile, so nothing downstream (`benilla-app`, `benilla`) could
   build at `680c6eac`. Fixed this round (see below).
2. **Preflight mislabels every Wrath session as NET OFF** (`preflight.rs:101-111` warns from
   `NetOffline` alone while `WrathNetPlugin` owns the real IO; `lib.rs:467` +
   `game_plugins.rs:131-138`). Corrupted the 2026-11-12 report's wire conclusions. Fixed this
   round.
3. **Spell-modifier table**: storage/range are 96 bits but `modifiers()` summed only `0..64`
   and `diff()` collapsed bits 64..96 into a boolean. Partially fixed this round; full
   completion is scoped below.
4. **`read_inspect_honor` had no unit test** (25-byte reply decoder). Fixed this round.
5. **Global `GetText` (locale lookup) is still missing** — the AUTO-01 leftover. Same root as
   the `benilla-app` honor-frame test blocker: those tests load
   `Interface\FrameXML\LocaleProperties.lua` (`ui_script/test_ui.rs` path), which is not
   available in the test environment, so the tests panic instead of running. Implementing the
   global (or shipping a minimal `LocaleProperties.lua` fixture) would unblock the honor tests
   and close the `GetText (x7)` runtime errors together.
6. **AUTO-05 tail confirmed open**: `VoiceChatSpeakerTemplate` (undefined template, x220
   warnings; no definition found in the installed Interface tree), `MoneyFrame.lua:274 money`
   nil (x63; host has `money_frame_tests.rs` coverage for `staticMoney`, the failing path is a
   different frame state), `ChannelFrame.lua:716 texture` nil (x8), and the post-hook
   `bartender4/ActionButton.lua:453 icon` nil — all same class: a native or object the FrameXML
   expects returns nil.

  `WrathInput` and routes through the new pure `net_offline_finding(wrath_owns_net, offline)`.
  A Wrath session is silent (its parked `NetOffline` is the design); stock capture keeps the

  `2026-11-13-anvil-preflight.md`.
- **Spell modifiers** (Forge, `crates/benilla-app/src/spell/mods.rs` only): `modifiers()` now

  out-of-range packet test now exercises bits 96/97 (in-range means 0..=95); 3 new tests.
  `diff()` still returns the existing `ModsDiff { bits: u64, class_family: bool }` — high-word
  changes remain collapsed into `class_family` (coarse but correct: `with_mods` rebuilds
  everything on it). Detail and consumer map: `2026-11-13-forge-spell-mods.md`.

  `impl Default for PetLoyaltyNames` in `crates/benilla-formats/src/pet_stats.rs` — required
  for any `benilla-app` verification; the E0599 came from `680c6eac`.
- **Protocol decoder tests** (coordinator, `crates/benilla-protocol-wrath/src/gameplay.rs`):
  `inspect_honor_decodes_the_25_byte_12340_reply`,
  `inspect_honor_zero_body_decodes_to_zeroed_fields`,

## Open: full 96-bit spell-modifier completion (designed change, not a hotfix)

`SpellDisplay::spell_family_flags` is `u64` (`benilla-formats/src/spells/display.rs:48`); the
third family word lives only in `SpellCatalog::spell_family_flags_96`
(`benilla-formats/src/spells/mod.rs:401-409`) and never reaches the read path, so bits 64..95
are stored, accepted and diffed-coarsely but never summed into values. Two designs:

- **Field on `SpellDisplay`** (`spell_family_flags_high: u32`, column 163): honest but breaks
  562 struct literals across 89 files (`git grep -c "SpellDisplay {"`) — mechanical, large.
- **Side carrier**: `SpellModifiers` holds the caster-class 96-bit family view or the read path
  consults `spell_family_flags_96(spell_id)`; touches the `benilla_formats::SpellMods` trait
  contract and the `spell_feed.rs`/`spell_deps.rs` read sites only (3 + 2 sites), plus
  `read_bits`/`mod_bits` high-word tracking for tooltip rebuild precision.

Related smaller pieces when this lands: `ModsDiff.high_bits` (struct literals at
`ui_tooltip/deps_tests.rs:1667/:1679`, consumer `with_mods` at `spell_deps.rs:268`), and
`read_bits()`/`mod_bits` staying low-word-only (documented) with the high-word rebuild handled
through the existing coarse path.
